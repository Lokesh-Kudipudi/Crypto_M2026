1. A hash is a fingerprint

Change one character, and about half of the 256 output bits flip. That's the avalanche effect.

SHA-256 of A

SHA-256 of B

Bits that differ

The output is always 256 bits, so a whole PDF and a two-word message give fingerprints of the same size. You can't work backwards from one to the input.

3. Why tokens are stored only as hashes

Session tokens, claim codes and share links act like keys. If the database stored them as they are, a stolen copy would let an attacker use every one.

A plain, fast hash is safe here because tokens are random: 256 bits for tokens and about 98 bits for claim codes. There's nothing to guess. Passwords are different, as the next section shows.

4. Why fast hashes fail for passwords

People choose guessable passwords. This attack tries a word list against a stolen unsalted SHA-256 hash, using your real browser speed.

Stolen database value

Two users, same password

UserUnsalted SHA-256With a random salt

Without salts, equal passwords give equal hashes, and one lookup table works on every account. A random salt forces the attacker to attack each account separately.
