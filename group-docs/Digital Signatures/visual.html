1. Keys: easy forwards, infeasible backwards

A private key is a number k. The public key is the curve point k × G. Computing it is fast, but recovering k from the point is the elliptic curve discrete logarithm problem.

A toy curve: y² = x³ + 7 over a field of 97 elements. The real curve has the same equation, with about 2256 points.

Public point k × G on the toy curve

The points jump around with no visible pattern, so seeing the point doesn't reveal k. On this toy curve you could try every k, but on the real one you couldn't.

2. Sign, then recover the signer

Ethereum doesn't need the public key sent with a signature. It can recover the signer from the signature and the message, then check who that is.

Digest z = keccak256(message)

Random k, used once

r = x coordinate of k × G

s = (z + r × private key) / k

Verifier

Address recovered from (r, s, v) and this message

Edit the received message and the recovered address changes completely. There's no "invalid" alarm in recovery: it simply gives someone else's address, so the system must compare it with the expected signer.

4. Signature malleability

If (r, s) is valid, then so is (r, n − s) with the recovery bit flipped. Anyone can make this second form without the private key. The project rejects it by accepting only s in the lower half.

FormsMaths recoversOpenZeppelin ECDSA

The twin recovers the same signer, so a system that used the signature as a unique ID could be fooled. Enforcing one valid form removes this. publishBatch also rejects duplicate roots.

5. Linking a wallet with personal_sign

A university must show it controls a wallet before an admin can approve it. Signing a one-time code proves this without revealing the private key or sending a transaction.

  1. Challenge: the server creates a random code and stores it on the user's row.
  2. Sign: the wallet adds the prefix "\x19Ethereum Signed Message:\n" + length, hashes the message and signs it.
  3. Verify: the server recovers the signer, compares it with the claimed wallet and clears the code.

6. Why k must be secret and never repeat

This shows why signing has to be left to a wallet. If two signatures share a k, simple algebra reveals the private key.

k = (z1 − z2) / (s1 − s2)  mod n
private key = (s1 × k − z1) / r  mod n

Real private key

Key the attacker computed

The project never handles k. MetaMask signs, and modern wallets derive k deterministically (RFC 6979), so it's not left to a random generator.
