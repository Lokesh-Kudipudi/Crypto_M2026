1. A commitment hides a value and locks it in

A CGPA has only about 1,000 likely values. Without a salt, its hash can be cracked by trying each one. This attack runs live.

Without a salt: keccak256("cgpa", value)

With a 32-byte salt: keccak256(0x00, "cgpa", value, salt)

Hiding: the hash reveals nothing without the salt. Binding: the student can't later reveal a different value, because it wouldn't produce the same hash.

4. Why the hashes have different prefixes

    
An inner node is the hash of 64 bytes. Without separate prefixes, an attacker can present those 64 bytes as if they were a certificate. It's called a second-preimage attack.

    

      
        
        
      
      
    

    

      
Batch root on-chain

      
Fake "certificate": two child hashes joined together

    

    

    
The project's contract applies 0x02 to certificate roots and 0x01 to inner nodes, so a node's hash can't equal a leaf's hash. The test at certificateRegistry.js:154 checks this.

  


  

    
5. Handling an odd number of nodes

    
When a level has an odd count, one common method pairs the last node with itself. That lets two different lists share one root.

    

      
RuleRoot of [A, B, C]Root of [A, B, C, C]Same root?

      
    

    
Bitcoin's block tree has this weakness, recorded as CVE-2012-2459. This project promotes the odd node unchanged, so the two lists get different roots.
